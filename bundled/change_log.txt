Most Recent Changes (v1.2.0 — Linux GTK4 port):

~ Added Opus export (.opus via libopus). Quality is a VBR target (64k–256k, default 192k) and ffmpeg resamples to 48 kHz.
~ Changed the default save format for new installs and missing settings to 16-bit FLAC. Existing settings.json values are left unchanged.

Previous Release (v1.1.1 — Linux GTK4 port):

Highlights:

~ Added the public uvr command-line interface for separation, ensembles, Audio Tools, model management, profiles, validation, reports, batch jobs, benchmarking, and shell completion.
~ Expanded the Download Center and model catalogue with official UVR metadata, Politrees resources, fork-curated extras, and the mvsepless community index.
~ Added exact canonical model IDs across the GTK application, CLI, saved jobs, dependencies, and custom-model workflows.
~ Introduced reviewed stem semantics so model selection, output names, karaoke/backing-vocal behavior, and ensembles agree on the stems a model produces.
~ Reworked the Linux documentation around practical GTK and CLI workflows, with expanded model/code provenance, credits, and research references.

Models and Download Center:

~ Added compatibility for MSST SCNet Masked and SCNet Tran checkpoints, HyperACE variants, PoPE-based PolarFormer checkpoints, and the BS-RoFormer Large Inst v2 architecture.
~ Added support for Mel-Band and Band-Split RoFormer skip-connection checkpoint variants.
~ Added canonical display names, per-stem SDR information, catalogue stem/configuration evidence, and clearer unsupported-model diagnostics.
~ Added registration and validation for custom Demucs models, including explicit version and source-layout metadata.
~ Improved catalogue caching, stale-while-revalidate behavior, deduplication, source isolation, offline access, and Download Center refresh performance.
~ Improved download progress accuracy, failure reporting, catalogue matching, and refresh behavior after models change on disk.

Stems, ensembles, and output:

~ Added concept-based stem routing for two-stem, karaoke, four-stem, and multi-stem models, including reviewed derived instrumental outputs.
~ Preserved explicit stem selections across GTK settings, CLI jobs, profiles, vocal splitters, and retained ensemble-member exports.
~ Made ensemble eligibility and pairing use stable semantic stem roles, with safer handling of incomplete members and focused outputs.
~ Improved long-file processing with chunking, overlap handling, progress accounting, and CUDA out-of-memory recovery with segment backoff.
~ Improved export finalization, collision handling, failure reporting, output promotion, and rollback of interrupted or failed CLI batches.
~ Added run-aware model caching, classic MDX batching, CUDA autocast controls, and additional CUDA/ONNX performance tuning.

Interface, reliability, and tooling:

~ Added typed JSON settings, validated overrides, and consistent shared settings across Separation, Ensemble, and Audio Tools pages.
~ Added drag-and-drop across the main window, combined output format/quality controls, live option summaries, and clearer inapplicable-setting states.
~ Reduced startup and Download Center work with lazy model population, cached checkpoint hashes, deferred refreshes, and lighter console updates.
~ Added structured diagnostic logging and clearer errors for invalid models, missing configurations, failed exports, and unavailable output folders.
~ Added model probe, model sweep, catalogue publication, and stem-audit tooling with reproducible offline checks and safer atomic outputs.
~ Expanded automated type checking and hermetic test coverage for GTK, CLI, catalogue, model identity, stem routing, ensembles, and audio exports.

Previous Release (v1.0.0 — Linux GTK4 port):

~ First public release of the Linux GTK4 / libadwaita port (PyGObject), built on upstream UVR v5.6.
~ GTK4 interface with libadwaita styling, keyboard shortcuts, and light/dark color scheme support.
~ Help Hints on controls; tooltip text consolidated for clearer reading.
~ About dialog with credits, resources, license, and release notes.
~ Error Log window for troubleshooting failed runs.
~ Saved settings profiles and saved ensemble presets.
~ Align Inputs UI with a dedicated dual-input pairs row.
~ FLAC export bit-depth option.
~ Writable runtime data can live outside the install tree via UVR_DATA_DIR (models, settings, profiles, ensembles).
~ NVIDIA GPU acceleration for MDX/ONNX inference when CUDA is installed.
~ Apollo music restoration and audio tools (time stretch, pitch shift) in the GTK shell.
~ GLib debug logging via G_MESSAGES_DEBUG (replaces UVR_DEBUG); optional UVR_LOG_FILE mirror; uvr-trace or UVR_VERBOSE=1 for high-frequency internals (uvr-console removed).
~ Expanded debug tracing across startup, downloads, workers, and separation engines.
~ Cleaner shutdown and stop/cancel handling during active conversions.
~ Fixed MDX two-stem export, model download regressions, and run failure dialogs.
~ Reorganized codebase: ui/, core/, engines/, ml/, bundled/, vendor/demucs/.

Upstream UVR v5.5 (included in this port):

~ Fixed Download Center model list issue.
~ Fixed audio clip in ensemble mode.
~ Fixed output model name issue in ensemble mode.
~ Added "Batch Mode" for MDX-Net to increase performance.
    ~ Batch Mode is more memory efficient.
    ~ Batch Mode produces the best output, regardless of batch size.

Fixes & Changes going from UVR v5.4 to v5.5:

~ The progress bar is now fully synced up with every process in the application.
~ Fixed low-resolution icon.
~ Added the ability to download models manually if the application can't connect 
   to the internet.
~ Drag-n-drop is functional across all os platforms.
~ Resolved mp3 tag issue in MacOS version.

Performance:

~ Model load times are faster.
~ Importing/exporting audio files is faster.

MacOS M1 Notes:

~ The GPU Conversion checkbox will enable MPS for GPU acceleration. However,
   only the VR Architecture models are currently compatible with it.

New Options:

~ Select Saved Settings option - Allows the user to save the current settings 
   of the whole application. You can also load a saved setting or reset them to 
   the default.
~ Right-click menu - Allows for quick access to important options.
~ Help Hints option - When enabled, users can hover over options to see a pop-up 
   text that describes that option. The right-clicking option also allows copying 
   the "Help Hint" text.
~ Secondary Model Mode - This option is an expanded version of the "Demucs Model" 
   option that was only available to MDX-Net. Except now, this option is available 
   in all three AI Networks and for any stem. Any model can now be Secondary, and 
   the user can choose the amount of influence it has on the final result.
~ Robust caching for ensemble mode, allowing for much faster processing times.
~ Clicking the "Input" field will pop up a window allowing the user to review the selected audio inputs. Within this menu, users can:
    ~ Remove inputs.
    ~ Verify inputs.
    ~ Create samples of chosen inputs.
~ "Sample Mode" option - Allows the user to process only part of a track to sample 
   settings or a model without running a full conversion.
    ~ The number in the parentheses is the current number of seconds the generated 
       sample will be.
    ~ You can choose the number of seconds to extract from the track in the "Additional 
       Settings" menu.

VR Architecture:

~ Ability to toggle "High-End Processing."
~ Ability to change the post-processing threshold.
~ Support for the latest VR architecture
    ~ Crop Size and Batch Size are specifically for models using the latest 
       architecture only.

MDX-NET:

~ Denoise Output option results in cleaner results, 
   but the processing time will be longer. This option has replaced Noise Reduction.
~ Spectral Inversion option uses spectral inversion techniques for a 
   cleaner secondary stem result. This option may slow down the audio export process.
~ Secondary stem now has the same frequency cut-off as the main stem.

Demucs:

~ Demucs v4 models are now supported, including the 6-stem model.
~ Ability to combine remaining stems instead of inverting selected stem with the 
   mixture only when a user does not select "All Stems".
~ A Pre-process model that allows the user to run an inference through a robust 
   vocal or instrumental model and separate the remaining stems from its generated 
   instrumental mix. This option can significantly reduce vocal bleed in other 
   Demucs-generated non-vocal stems.
    ~ The Pre-process model is intended for Demucs separations for all stems except
       vocals and instrumentals.

Ensemble Mode: 

~ Ensemble Mode has been extended to include the following:
    ~ Averaging is a new algorithm that averages the final results.
    ~ Unlimited models in the ensemble.
    ~ Ability to save different ensembles.
    ~ Ability to ensemble outputs for all individual stem types.
    ~ Ability to choose unique ensemble algorithms.
    ~ Ability to ensemble all 4 Demucs stems at once.
